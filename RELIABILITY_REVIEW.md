## Singleton safety and limits
Each claim is a short storage transaction on paper-executor-v1. Only the claimant runs the entire check outside the transaction; its durable active marker prevents any other client from claiming while asynchronous work is in progress. Completion must match the owner before it removes active and persists lastCompletedSlot/heartbeat. A transaction retry repeats only storage operations, never broker work.

A thrown runner error, process reset, lost response or failed completion write leaves active in place. This sacrifices availability to avoid a lease expiry permitting a second executor while a first may still act. There is no unsafe timeout-based release, no automatic recovery, and no broker replay. Two object instances using one mock durable store are tested; this does not substitute for Cloudflare runtime integration testing.

Manual recovery proposal (NOT implemented): stop all executors and revoke any old deployment's ability to run; prove the old instance has stopped; inspect/reconcile paper orders and positions; record an operator-approved recovery audit; clear only the matching active marker via a reviewed one-off maintenance procedure. No public unlock route. A running old deployment cannot be fenced by Alpaca using our storage token, so do not clear active merely because it looks old.

The mutex protects callers using the same namespace/identity. Deployment cutover must exclude old Actions jobs, older Workers, other repository copies and manual account callers. Draft official CLIs are disabled and the schedule adapter is routed; arbitrary external code using the account is outside the lock. Use one namespace per account, never point multiple active deployments at different namespaces for the same account. Changing credentials/account identity or deleting/migrating the namespace requires an outage/reconciliation plan.

Do not wrap an entire broker operation in blockConcurrencyWhile: Cloudflare documents a thirty-second timeout/reset for that method. This draft uses short transactional storage steps instead. See [Durable Object state](https://developers.cloudflare.com/durable-objects/api/state/).
